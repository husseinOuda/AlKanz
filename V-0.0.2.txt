1. ✅ الشيكل ILS

دعم الشيكل بشكل احترافي ⭐⭐⭐⭐

نريد أن نجعل نظام العملات نفسه أكثر احترافية.

مثلاً:

```
العملة:
[ شيكل إسرائيلي (ILS)]

رمز العملة:
[ ₪ ]

الكود:
ILS

المنازل العشرية:
[ 2 ]

موضع الرمز:
[ بعد المبلغ ]

مثال:
125.50 ₪
```

لكن الأهم أن نراجع **كل أماكن عرض العملة**:
* POS
* المنتجات
* الفواتير
* العملاء
* المصروفات
* التقارير
* Dashboard
* Excel
* PDF
* الطباعة الحرارية

حتى لا يكون لدينا مكان يعرض:
```
₪ 100
```

ومكان آخر:
```
100 ر.س
```

بسبب قيمة قديمة.

2. المرتجعات

# المرتجعات والاستبدال ⭐⭐⭐⭐⭐

النظام قوي في **إلغاء الفاتورة**، لكن الإلغاء ليس هو نفسه المرتجع التجاري.

نحتاج:

### مرتجع كامل
```
فاتورة #INV-2026-00125
       ↓
مرتجع كامل
       ↓
إعادة المنتجات للمخزون
       ↓
إرجاع المبلغ للعميل
```

### مرتجع جزئي مثلاً:
```
الفاتورة:
10 × منتج A
5 × منتج B
3 × منتج C
```

العميل يعيد:
```
2 × منتج A
```
فتصبح حركة منفصلة.

### والأفضل نضيف في تفاصيل الفاتورة:
**[إرجاع]**
وبعد الضغط:
```
اختر المنتجات
الكمية المرتجعة
سبب المرتجع
طريقة إعادة المبلغ
```
مع سجل كامل للمرتجعات.

3. طرق الدفع المتعددة

# طرق دفع أكثر احترافية ⭐⭐⭐⭐

حاليًا النموذج الأساسي يركز على:
```
نقدي
آجل
```

بينما المصروفات لديها طرق دفع أكثر.

نريد توحيد نظام المدفوعات. مثلاً:
```
نقدي
تحويل بنكي
بطاقة
شيك
محفظة إلكترونية
آجل
```

وفي الفاتورة:
```
الإجمالي: 450 ₪

المدفوع:
[ 300 ₪ ]

طريقة الدفع:
[ نقدي ]

المتبقي:
150 ₪
```

والأفضل إضافة:
### دفع مختلط مثلاً:
```
الإجمالي: 1,000 ₪

نقدي:       400 ₪
تحويل:      300 ₪
بطاقة:      300 ₪
```

فهي إضافة ممتازة لنظام POS.

4. الورديات والصندوق

# نظام الورديات والصندوق ⭐⭐⭐⭐⭐

الموجود حاليًا: 
* نقدي
* آجل
* مصروفات
* مدفوعات

لكن لا يوجد مفهوم:
> **صندوق الكاشير**

وهذا مهم جدًا.

نضيف:
### فتح وردية
```
فتح وردية
────────────
الرصيد الافتتاحي: 500 ₪
```

ثم خلال اليوم:
```
مبيعات نقدية
+ 3,250 ₪

مدفوعات عملاء
+ 800 ₪

مصروفات نقدية
- 250 ₪
```

وفي النهاية:
```
الرصيد المتوقع
4,300 ₪

المبلغ الفعلي
4,280 ₪

الفرق
-20 ₪
```

ثم:
**إغلاق الوردية**
مع تقرير كامل.

وهنا يصبح النظام مناسبًا أكثر للعمل مع كاشير فعلي.

6. تحسين تقارير الأرباح

# حساب ربح أكثر دقة ⭐⭐⭐⭐⭐

النظام عنده:
```
unitCostMinor
```

ويحتفظ بتكلفة المنتج داخل سطر الفاتورة تاريخيًا.

لكن نريد تطوير التقارير إلى:
### هامش الربح
```
المبيعات
10,000 ₪

تكلفة البضاعة
6,000 ₪

مجمل الربح
4,000 ₪

الهامش
40%
```

ثم:
```
المصروفات
1,500 ₪

صافي الربح
2,500 ₪
```

والأفضل تقرير:
> **الأكثر ربحية**
بدلاً من "الأكثر مبيعًا" فقط.

مثلاً:
| المنتج | المبيعات |   الربح |
| ------ | -------: | ------: |
| A      |  5,000 ₪ | 2,000 ₪ |
| B      |  8,000 ₪ |   800 ₪ |
| C      |  3,000 ₪ | 1,500 ₪ |

وهذا مفيد.
