# مراجعة الأمان والخصوصية

نطاق المراجعة: تطبيق ثابت يعمل بالكامل في متصفح المستخدم، بلا خادم وبلا حسابات
وبلا أي اتصال شبكي بعد تحميل الأصول.

---

## 1. نموذج التهديد

| ما هو **خارج** النطاق | لماذا |
|---|---|
| اعتراض الشبكة | لا يُرسل أي شيء إلى أي خادم بعد تحميل الأصول |
| اختراق قاعدة بيانات مركزية | لا توجد قاعدة مركزية |
| سرقة بيانات اعتماد | لا توجد حسابات ولا كلمات مرور ولا رموز |
| سرقة بيانات بطاقات | **لا نعالج ولا نخزّن أي بيانات دفع** |

| ما هو **داخل** النطاق | التخفيف |
|---|---|
| XSS عبر مدخلات المستخدم | بناء DOM آمن + CSP (§2) |
| XSS عبر ملف نسخة احتياطية معدّل | فحص كامل قبل الاستعادة (§4) |
| تلف البيانات من استيراد فاسد | تحقق وتطبيع على كل مسار إدخال (§3) |
| فقد البيانات | معاملات ذرّية + نسخ احتياطي + تخزين دائم (§5) |
| وصول فيزيائي للجهاز | **غير مخفَّف — انظر §7** |

## 2. الحماية من XSS

### 2.1 لا `innerHTML` إطلاقاً

كل الـ DOM يُبنى عبر `h()` في [`src/utils/dom.js`](../src/utils/dom.js) الذي يستخدم
`createElement` و`textContent` فقط. الدالة **ترمي استثناءً** عند محاولة تمرير `html`:

```js
case 'html':
  throw new Error('h(): استخدام html ممنوع. استخدم text أو عناصر فرعية.');
```

التحقق من الالتزام:

```bash
grep -rn "innerHTML\|outerHTML\|insertAdjacentHTML\|document.write" src/ sw.js
# لا نتائج
```

`DOMParser` يُستخدم في `xlsx.js` فقط، بنوع `application/xml` (لا ينفّذ سكربتات)،
ولا تُدرَج نتيجته في الصفحة إطلاقاً — تُقرأ نصوص الخلايا منها فقط.

### 2.2 Content Security Policy

```
default-src 'self'; script-src 'self'; style-src 'self';
img-src 'self' data: blob:; font-src 'self'; connect-src 'self';
object-src 'none'; base-uri 'none'; form-action 'none'
```

- `script-src 'self'` بلا `unsafe-inline` ولا `unsafe-eval` ⇒ لا سكربت مضمّن ولا `eval`.
- `connect-src 'self'` ⇒ أي محاولة إرسال بيانات لجهة خارجية تُحجب على مستوى المتصفح.
- `img-src` يسمح بـ `data:` و`blob:` لأن صور المنتجات والمرفقات مخزّنة كـ data URL.
- `object-src 'none'`, `base-uri 'none'`, `form-action 'none'` تغلق نواقل شائعة.

**التنسيقات الديناميكية تحت CSP صارمة:** لا نحقن `<style>` ولا نضع سمة `style` في الترميز.
كل تنسيق ديناميكي يُكتب عبر CSSOM (`el.style.setProperty`) وهو غير محكوم بـ `style-src`.
لهذا السبب أيضاً وُضع حجم الورق الحراري في ملف CSS منفصل تُبدَّل سمة `media` الخاصة به.

> **⚠️ إجراء مطلوب عند النشر:** `frame-ancestors` **لا تعمل عبر `<meta>`** (يتجاهلها
> المتصفح ويسجّل تحذيراً). أضفها كترويسة HTTP:
> `Content-Security-Policy: frame-ancestors 'none'`
> أو `X-Frame-Options: DENY`.

### 2.3 عزل اتجاه النص

كل قيمة لاتينية داخل نص عربي تُغلَّف بـ `<bdi dir="ltr">`. هذا يمنع محارف تحكم الاتجاه
داخل اسم منتج من قلب ترتيب عرض بقية السطر. إضافةً لذلك، `normalizeText` تحذف محارف
`U+200B–U+200F` و`U+202A–U+202E` و`U+FEFF` من كل مدخل.

## 3. التحقق من المدخلات

كل ما يدخل قاعدة البيانات يمر عبر [`src/validation/validators.js`](../src/validation/validators.js).
لا يوجد مسار كتابة يتجاوزها.

### الحدود المفروضة

| العنصر | الحد |
|---|---|
| اسم / بيان | 120 حرفاً |
| SKU / Barcode | 40، وSKU يُقيَّد بـ `[A-Z0-9\-_.]` |
| الوصف | 500 |
| الملاحظة | 200 |
| الكمية | عدد صحيح، ≤ 1,000,000 |
| المبلغ | عدد صحيح بوحدة صغرى، ≤ 99,999,999,999 |
| صورة منتج | 5MB، `image/png\|jpeg\|webp` |
| مرفق مصروف | 5MB، الصور + `application/pdf` |
| ملف نسخة احتياطية | 100MB، `.json` |
| ملف استيراد Excel | 15MB، `.xlsx` |

### التطبيع

- **الأرقام العربية-الهندية والفارسية** (`٠١٢…`, `۰۱۲…`) تُحوَّل إلى لاتينية قبل التحليل.
- **الفاصلة العشرية العربية** `٫` تُحوَّل إلى `.`.
- **فواصل الآلاف** والمسافات غير الفاصلة تُزال.
- **SKU** يُوحَّد إلى حروف كبيرة.
- **الهاتف** يُقلَّص إلى أرقام و`+` فقط.

### فحص الملفات قبل القراءة

`validateFile()` تفحص الوجود والحجم والنوع **قبل** أي قراءة، فلا يُقرأ ملف 500MB إلى
الذاكرة لاكتشاف أنه مرفوض. وامتداد الملف يُفحص أيضاً لأن `file.type` قابل للتزوير.

### الصور

الصور لا تُخزَّن كما رُفعت: تُفكّ عبر `createImageBitmap` (يفشل على ملف ليس صورة فعلاً
مهما كان امتداده)، ثم تُعاد رسمها على `<canvas>` وتُصدَّر JPEG. **هذا يُسقط أي حمولة
مضمّنة في بيانات EXIF أو أجزاء الملف** لأن الناتج بكسلات معاد ترميزها.

## 4. أمان الاستعادة

ملف النسخة الاحتياطية مدخل **غير موثوق** — قد يُعدَّل يدوياً أو يأتي من مصدر آخر.

`inspectBackupFile()` تفحص **قبل أي كتابة**:

1. النوع والحجم والامتداد.
2. صلاحية JSON.
3. `format === 'sales-system-backup'`.
4. `schemaVersion`: أحدث من التطبيق ⇒ **رفض**؛ أقدم ⇒ قبول مع تحذير.
5. كل متجر مصفوفة.
6. **كل سجل في كل متجر** يُفحص مقابل شكل معرَّف (`RECORD_SHAPES`): وجود الحقول
   المطلوبة ونوعها (`string` / عدد صحيح). فحص **كامل لا بالعيّنة** — البيانات المالية
   لا تحتمل فحصاً جزئياً.
7. **كل `data:` URL** يُفحص بنمط صارم:
   ```js
   /^data:image\/(png|jpeg|webp);base64,[A-Za-z0-9+/=]+$/
   ```
   وهذا يرفض `javascript:` و`data:text/html` وأي محتوى قابل للتنفيذ.
8. **تكامل مرجعي**: سطر فاتورة بلا فاتورة مرتبطة ⇒ رفض.

الاستعادة نفسها:
- تُنشأ **نسخة أمان تلقائية** من الوضع الحالي أولاً.
- المسح والكتابة داخل **معاملة IndexedDB واحدة**؛ أي خطأ يُجهضها وتبقى البيانات الحالية
  كما هي بالضبط. مختبَر صراحةً.
- **لا دمج**: إما استبدال كامل بملف صالح أو رفض بسبب واضح. لا يُدمج سجل مجهول بصمت.

## 5. سلامة البيانات

| الضمان | كيف |
|---|---|
| البيع ذرّي | فاتورة + سطور + حركات + عدّاد الترقيم في معاملة واحدة |
| البيع الفاشل بلا أثر | إجهاض كامل؛ مختبَر بـ 7 حالات فشل |
| الإلغاء لا يتضاعف | يُرفض إلغاء فاتورة ملغاة |
| المخزون = مجموع حركاته | `applyMovement` هو المسار الوحيد الذي يكتب `quantity` |
| لا مخزون سالب | مفروض افتراضياً؛ يتطلب تفعيلاً صريحاً في الإعدادات |
| لا أرقام فواتير مكررة | فهرس فريد + الزيادة داخل نفس المعاملة |
| لا تشويه للتقارير التاريخية | لقطات السعر والتكلفة والاسم داخل سطر الفاتورة |
| لا أخطاء عشرية | حساب بأعداد صحيحة فقط |
| لا انحراف في الأرصدة | رصيد العميل محسوب من الحركات لا محفوظاً |

## 6. الخصوصية

- **لا تتبّع ولا تحليلات ولا طلبات خارجية.** `connect-src 'self'` يجعل هذا قابلاً للتحقق.
- **لا CDN**: كل الأصول محلية، فلا يعرف أي طرف ثالث أنك تستخدم التطبيق.
- **لا يُخزَّن**: كلمات مرور، مفاتيح API، بيانات بطاقات، أو أي سر.
- **البيانات مرتبطة بالنطاق (Origin)**: لا تُشارك بين المتصفحات ولا الأجهزة.
- **التسجيل التقني** (`console`) يحتوي رسائل تشخيصية فقط بلا محتوى سجلات حساسة.

## 7. حدود معروفة — بصراحة

### 7.1 لا مصادقة ولا صلاحيات

**أي شخص يفتح المتصفح على هذا الجهاز يرى ويعدّل كل البيانات.**

قرار صريح: **لم نضف PIN محلياً.** PIN مخزّن في IndexedDB يمكن لأي شخص لديه وصول
للجهاز تجاوزه من أدوات المطوّر في ثوانٍ. تقديمه كـ«حماية» يعطي المستخدم أماناً وهمياً
أسوأ من غيابه المعلن.

المصادقة والصلاحيات الحقيقية تتطلبان Backend — انظر [`future-backend.md`](future-backend.md).

**التخفيف التشغيلي:** استخدم قفل شاشة نظام التشغيل وحساب مستخدم منفصل، وفعّل تشفير القرص.

### 7.2 البيانات غير مشفّرة على القرص

IndexedDB يُخزَّن كما هو. تشفير من داخل المتصفح يتطلب مفتاحاً، وأي مفتاح مخزّن محلياً
قابل للاستخراج بنفس مستوى الوصول، وأي مفتاح من كلمة مرور يعني فقد كل البيانات عند نسيانها.

**التخفيف:** تشفير القرص على مستوى النظام (BitLocker / FileVault / LUKS).

### 7.3 ملف النسخة الاحتياطية نص صريح

ملف JSON يحتوي كل بيانات المتجر بلا تشفير. **احفظه في مكان آمن** — تشفيره بأداة نظام
(7-Zip بكلمة مرور، أو مجلد سحابي مشفّر) مسؤولية تشغيلية.

### 7.4 لا تدقيق حقيقي للمستخدمين

`inventoryMovements` يسجّل «المستخدم» أو «النظام» فقط. بلا حسابات لا يمكن معرفة **من**
نفّذ الحركة. السجل يفيد في تتبّع **ما حدث ومتى**، لا **من فعله**.

### 7.5 حدود الفحص المرجعي

IndexedDB لا يفرض مفاتيح أجنبية. الاتساق مفروض في طبقة التطبيق. تعديل يدوي مباشر على
قاعدة البيانات من أدوات المطوّر يمكن أن يكسر الاتساق — وهو خارج نموذج التهديد.

## 8. الاعتماديات والتراخيص

**عدد اعتماديات وقت التشغيل: صفر.**

| ما كان يمكن استخدامه | ماذا فعلنا بدلاً منه |
|---|---|
| Bootstrap RTL | CSS مخصّص |
| Bootstrap Icons | أيقونات SVG مضمّنة |
| Chart.js | مخططات SVG مكتوبة |
| SheetJS / xlsx | `CompressionStream` + ZIP يدوي |
| خطوط من CDN | Tajawal مستضاف محلياً (OFL 1.1، ~72KB) |

أثر أمني مباشر: **لا سطح هجوم من سلسلة التوريد** (supply chain)، ولا حاجة لمراقبة
ثغرات الاعتماديات، ولا تدقيق تراخيص.

أدوات التطوير في `tools/` تستخدم `ws` من الحزم العامة (اختيارياً) ومتصفح النظام،
وهي **غير جزء من المنتج المنشور**.

## 9. قائمة فحص أمنية قبل النشر

- [ ] أضف ترويسة `Content-Security-Policy: frame-ancestors 'none'` أو `X-Frame-Options: DENY`.
- [ ] انشر على HTTPS فقط.
- [ ] أضف `Strict-Transport-Security` و`X-Content-Type-Options: nosniff`.
- [ ] تأكد أن `sw.js` بلا كاش HTTP طويل الأمد.
- [ ] لا تضع بيانات حقيقية على جهاز مشترك بلا حساب مستخدم منفصل.
- [ ] فعّل التخزين الدائم من شاشة الإعدادات بعد أول تشغيل.
- [ ] ضع جدولاً للنسخ الاحتياطي وخزّن النسخ **خارج الجهاز**.
